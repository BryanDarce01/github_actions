# Artifacts en GitHub Actions

## 1. ¿Qué son?

Los **Artifacts (artefactos)** son archivos o conjuntos de archivos que se generan durante la ejecución de un workflow y que queremos conservar, compartir o analizar posteriormente.

Los Jobs suelen producir recursos que pueden ser útiles después de terminar su ejecución. Por ejemplo, un Job puede compilar una aplicación y generar archivos que otro Job necesitará para desplegarla.

Ejemplos:
- Archivos de un sitio web listo para desplegar (`dist/`, `build/`).
- Reportes de pruebas o de cobertura.
- Paquetes, instaladores y archivos binarios.
- Logs generados por nuestra propia aplicación.
- Archivos que queremos descargar o analizar después.

Estos recursos se conocen como **Artifacts** o **Job Artifacts**.

## 2. Subir un artefacto

GitHub Actions proporciona Actions para subir y descargar artefactos. Para subirlos utilizamos `actions/upload-artifact`.

```yaml
- name: Upload artifacts
  uses: actions/upload-artifact@v4
  with:
    name: dist-files
    path: dist/
```

- `uses`: indica qué Action utilizaremos.
- `actions/upload-artifact@v4`: Action oficial para subir artefactos.
- `with`: contiene los parámetros que recibe la Action.
- `name`: nombre con el que identificaremos el artefacto.
- `path`: archivo o carpeta que queremos subir.

Podemos subir un archivo individual o una carpeta completa.

## 3. Descargar manualmente desde GitHub

Una vez que termina la ejecución del workflow:

1. Entrar al repositorio y abrir **Actions**.
2. Seleccionar la ejecución del workflow.
3. Buscar la sección **Artifacts** en la página de esa ejecución.
4. Seleccionar el artefacto para descargarlo, normalmente como un archivo comprimido.

Así podemos recuperar archivos que produjo el workflow sin tener que volver a ejecutar el proceso.

## 4. Compartir artefactos entre Jobs

Los Jobs normalmente se ejecutan en runners separados. Por eso, no debemos asumir que los archivos generados en el sistema de archivos de un Job estarán disponibles automáticamente en otro.

Podemos utilizar Artifacts para transferir esos archivos:

```yaml
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - name: Build
        run: |
          mkdir dist
          echo "Aplicación compilada" > dist/index.txt

      - name: Upload artifacts
        uses: actions/upload-artifact@v4
        with:
          name: dist-files
          path: dist/

  deploy:
    needs: build
    runs-on: ubuntu-latest
    steps:
      - name: Download artifacts
        uses: actions/download-artifact@v4
        with:
          name: dist-files
          path: dist/

      - name: Show downloaded files
        run: ls -R dist
```

El proceso es:

1. `build` genera la carpeta `dist/`.
2. `upload-artifact` guarda su contenido como un artefacto.
3. `deploy` espera a que termine `build` gracias a `needs: build`.
4. `download-artifact` recupera el artefacto en el runner de `deploy`.
5. El Job `deploy` ya puede utilizar los archivos descargados.

**Importante:** Artifacts permite compartir archivos entre Jobs, pero no significa que ambos Jobs compartan el mismo sistema de archivos.

## 5. Artifacts y Logs: ¿son lo mismo?

No. Aunque ambos pueden contener información útil de una ejecución, tienen propósitos diferentes.

- **Logs:** muestran la salida de los comandos y pasos ejecutados. GitHub conserva los registros de la ejecución del workflow.
- **Artifacts:** son archivos que decidimos guardar utilizando una Action como `actions/upload-artifact`.

Por ejemplo, la salida que produce `npm run build` en la terminal aparece en los logs. En cambio, la carpeta `dist/` puede subirse como artefacto para descargarla o utilizarla en otro Job.

Si queremos conservar un archivo de log generado por nuestra propia aplicación, también podemos subirlo como artefacto:

```yaml
- name: Upload application log
  uses: actions/upload-artifact@v4
  with:
    name: application-log
    path: logs/app.log
```

## 6. Retención de los Artifacts

Los artefactos tienen un período de retención; no se conservan indefinidamente. Podemos configurarlo con `retention-days`:

```yaml
- name: Upload artifacts
  uses: actions/upload-artifact@v4
  with:
    name: dist-files
    path: dist/
    retention-days: 7
```

En este ejemplo se solicita conservar el artefacto durante siete días, sujeto a los límites y políticas de GitHub.

**Idea clave:** un Artifact es un archivo o conjunto de archivos producido durante un workflow que queremos conservar, compartir entre Jobs o analizar posteriormente.
