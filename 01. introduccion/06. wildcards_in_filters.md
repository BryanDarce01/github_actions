# Comodines (Wildcards) en los filtros de GitHub Actions

## 1. ¿Qué son los comodines?

Los **wildcards** o comodines permiten crear patrones que coincidan con
varios nombres de ramas o rutas de archivos, sin tener que escribir cada
nombre individualmente.

Se utilizan, entre otros lugares, en los filtros:

-   `branches`
-   `branches-ignore`
-   `paths`
-   `paths-ignore`

## 2. Comodines principales

  -----------------------------------------------------------------------
  Patrón                              Significado
  ----------------------------------- -----------------------------------
  `*`                                 Coincide con cero o más caracteres,
                                      pero no atraviesa `/`.

  `**`                                Coincide con cero o más caracteres,
                                      incluyendo separadores `/`.

  `?`                                 Coincide con un solo carácter.

  `+`                                 Coincide con uno o más del elemento
                                      anterior.

  `!`                                 Niega un patrón; se utiliza para
                                      excluir coincidencias en listas de
                                      patrones.
                                      
  -----------------------------------------------------------------------

## 3. Ejemplos con ramas

### Todas las ramas que comiencen con `feature/`

``` yaml
on:
  push:
    branches:
      - 'feature/*'
```

Coincide, por ejemplo, con:

-   `feature/login`
-   `feature/navbar`

Pero `*` no atraviesa `/`, por lo que no coincide con
`feature/user/profile`.

### Ramas con cualquier cantidad de niveles

``` yaml
on:
  push:
    branches:
      - 'feature/**'
```

Puede coincidir con:

-   `feature/login`
-   `feature/user/profile`
-   `feature/api/auth`

La diferencia importante es que `**` sí puede atravesar `/`.

### Ramas que comiencen con `release-`

``` yaml
on:
  push:
    branches:
      - 'release-*'
```

Puede coincidir con `release-1.0`, `release-2.0`, etc.

## 4. Ejemplos con rutas de archivos

### Archivos dentro de una carpeta

``` yaml
on:
  push:
    paths:
      - 'src/**'
```

Coincide con archivos dentro de `src/`, incluyendo subcarpetas.

### Archivos Markdown en cualquier ubicación

``` yaml
on:
  push:
    paths:
      - '**/*.md'
```

Coincide con archivos `.md` en distintos niveles del repositorio.

### Archivos JavaScript directamente dentro de `src`

``` yaml
on:
  push:
    paths:
      - 'src/*.js'
```

El `*` no atraviesa `/`, por lo que este patrón coincide con archivos
`.js` directamente dentro de `src`, no con archivos en subcarpetas.

## 5. Patrones negativos con `!`

Podemos incluir un patrón y después excluir parte de sus coincidencias:

``` yaml
on:
  push:
    branches:
      - 'releases/**'
      - '!releases/**-alpha'
```

La intención es incluir ramas bajo `releases/`, excepto las que terminen
en `-alpha`.

El orden importa: un patrón negativo excluye coincidencias anteriores y
un patrón positivo posterior puede volver a incluirlas.

También podemos hacer algo parecido con rutas:

``` yaml
on:
  push:
    paths:
      - 'src/**'
      - '!src/docs/**'
```

## 6. ¿Por qué algunos patrones llevan comillas?

En YAML, ciertos caracteres tienen significado especial. Por claridad y
para evitar interpretaciones inesperadas, es buena práctica poner entre
comillas los patrones que contienen caracteres especiales, especialmente
`*`, `**`, `!` o `?`.

Por ejemplo:

``` yaml
branches:
  - 'feature/**'
```

**Idea clave:** `*` coincide dentro de un solo nivel de ruta; `**` puede
abarcar varios niveles. Esto permite filtrar ramas y carpetas de forma
flexible.
