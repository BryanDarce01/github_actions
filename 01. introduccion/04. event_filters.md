# Event Filters en GitHub Actions

## 1. ¿Qué son los Event Filters?

Los **Event Filters** (filtros de eventos) permiten limitar cuándo debe
ejecutarse un workflow, según condiciones como:

-   La rama involucrada.
-   Los archivos o rutas que cambiaron.

Son especialmente útiles con los eventos `push` y `pull_request`, porque
evitan ejecutar workflows cuando los cambios no afectan lo que queremos
comprobar.

## 2. Filtro `branches`

Permite especificar las ramas que deben activar el workflow.

``` yaml
name: Main branch workflow

on:
  push:
    branches:
      - main

jobs:
  example:
    runs-on: ubuntu-latest
    steps:
      - run: echo "Push a main"
```

En este caso, el workflow se ejecuta cuando se realiza un `push` a
`main`, pero no cuando se realiza a `develop`.

También se puede escribir:

``` yaml
on:
  push:
    branches: [main, develop]
```

### `branches` en un Pull Request

Cuando se utiliza con `pull_request`, el filtro `branches` evalúa la
**rama destino (base)** del Pull Request, no la rama de origen (head).

``` yaml
on:
  pull_request:
    branches: [main]
```

Esto significa que se activa para Pull Requests cuyo destino sea `main`,
independientemente de cómo se llame la rama desde la que se propone el
cambio.

## 3. Filtro `paths`

Permite ejecutar el workflow únicamente cuando se modifican archivos que
coinciden con las rutas especificadas.

``` yaml
on:
  push:
    paths:
      - 'src/**'
      - 'package.json'
```

El workflow se ejecutará si el push incluye cambios en archivos dentro
de `src/` o en `package.json`.

## 4. Filtro `paths-ignore`

Hace lo contrario: permite ignorar determinados archivos o rutas.

``` yaml
on:
  push:
    paths-ignore:
      - 'docs/**'
      - '*.md'
```

El workflow no se ejecutará cuando todos los archivos modificados
coincidan con los patrones ignorados.

Si el push incluye tanto archivos ignorados como archivos que no están
ignorados, el workflow sí puede ejecutarse.

## 5. Combinar filtros

Podemos combinar `branches` y `paths`:

``` yaml
on:
  push:
    branches:
      - main
    paths:
      - 'src/**'
```

En este ejemplo deben cumplirse ambas condiciones:

1.  El push debe ser a la rama `main`.
2.  Debe haber cambios dentro de `src/`.

No basta con cumplir solamente una de ellas.

## 6. `branches` frente a `branches-ignore`

-   `branches`: define las ramas que sí deben coincidir.
-   `branches-ignore`: define las ramas que deben excluirse.

No se deben utilizar `branches` y `branches-ignore` simultáneamente para
el mismo evento. Si necesitamos incluir y excluir patrones, podemos
utilizar patrones negativos (`!`) dentro de `branches`.

**Idea clave:** los filtros no cancelan una ejecución; determinan si el
evento cumple las condiciones para iniciar el workflow.
