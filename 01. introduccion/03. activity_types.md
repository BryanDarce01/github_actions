# Activity Types en GitHub Actions

## 1. ¿Qué son los Activity Types?

Un **Activity Type** (tipo de actividad) permite especificar qué acción
concreta de un evento debe provocar la ejecución de un workflow.

Un evento responde a la pregunta:

> ¿Qué sucedió en GitHub?

El Activity Type responde:

> ¿Qué acción específica ocurrió dentro de ese evento?

Por ejemplo, el evento `pull_request` puede producirse cuando alguien
abre un Pull Request, lo edita, lo vuelve a abrir o agrega nuevos
commits.

Si no especificamos Activity Types, GitHub utiliza los tipos
predeterminados definidos para ese evento.

## 2. Sintaxis

Se especifican mediante la propiedad `types`, dentro del evento:

``` yaml
name: Pull Request workflow

on:
  pull_request:
    types: [opened, synchronize]

jobs:
  example:
    runs-on: ubuntu-latest
    steps:
      - run: echo "Se abrió un PR o recibió nuevos commits"
```

En este ejemplo, el workflow se ejecuta cuando:

-   Se abre un Pull Request (`opened`).
-   Se agregan nuevos commits a un Pull Request (`synchronize`).

No se ejecutará por otras actividades de `pull_request` que no estén
incluidas en `types`.

## 3. Activity Types frecuentes de `pull_request`

  -----------------------------------------------------------------------
  Tipo                                Significado
  ----------------------------------- -----------------------------------
  `opened`                            Se abre un Pull Request.

  `edited`                            Se modifica información del Pull
                                      Request, como su título o
                                      descripción.

  `synchronize`                       La rama de origen recibe nuevos
                                      commits.

  `reopened`                          Se vuelve a abrir un Pull Request
                                      cerrado.

  `closed`                            Se cierra o se hace merge del Pull
                                      Request.

  `assigned`                          Se asigna a una persona.

  `unassigned`                        Se quita una asignación.

  `labeled`                           Se agrega una etiqueta.

  `unlabeled`                         Se elimina una etiqueta.

  `ready_for_review`                  Un Pull Request pasa a estar listo para revisión.
  
  `review_requested`                  Se solicita una revisión.
  
  -----------------------------------------------------------------------

La lista de tipos disponibles depende del evento. No todos los eventos
tienen los mismos Activity Types.

## 4. Tipos predeterminados

Si escribimos:

``` yaml
on:
  pull_request:
```

GitHub utiliza los Activity Types predeterminados de `pull_request`.
Entre ellos están `opened`, `synchronize` y `reopened`.

Si necesitamos reaccionar a otros tipos de actividad, debemos agregarlos
explícitamente con `types`.

## 5. Diferencia entre evento y Activity Type

``` yaml
on:
  pull_request:
    types: [opened, synchronize]
```

-   `pull_request`: el evento que queremos escuchar.
-   `types`: las actividades concretas que nos interesan.
-   `opened` y `synchronize`: los tipos de actividad seleccionados.

**Idea clave:** el evento identifica la clase de suceso y `types`
especifica qué actividad dentro de ese suceso debe activar el workflow.
